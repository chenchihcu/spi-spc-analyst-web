# RFC：匯入厚度與本回合鋼板厚度的資料流

- 狀態：提案；本次介面澄清依此方案，資料契約不變
- 日期：2026-10-30
- 範圍：「資料與規格 → 匯入與規格」的匯入厚度與目前回合厚度

## 1. 問題與目標

同頁有兩個鋼板厚度欄位，原標籤相同，使用者難以分辨哪個欄位會影響待匯入資料、哪個欄位控制正在分析的回合。

目標是清楚呈現厚度的生命週期，讓匯入厚度在套用時帶入新回合；回合建立後，厚度調整只影響該回合的分析設定，原始匯入紀錄仍保留當時使用的厚度。

非目標：雙向即時同步、修改既有雲端紀錄、建立跨回合或跨使用者的厚度預設值、變更 API 或資料庫 schema。

## 2. 現況與建議資料流

### 已確認現況

- `#inImpStencil` 是匯入表單欄位。高度百分比轉換會讀取此值；按「套用匯入」時，程式以此厚度驗證／換算，並將 `stencil` 寫入量測紀錄中繼資料及新回合設定。
- `#inStencil2` 顯示目前選取回合的 `S.stencil`。修改時執行 `applyStencil`，重算高度相關值、儲存回合設定並更新分析。
- 套用匯入並切換至新回合後，`syncControls` 會把回合的厚度顯示在 `#inStencil2`。資料庫量測紀錄保留匯入時的 `stencil`；本回合後續修改不會更新該紀錄。

### 建議方案：提交時單向帶入

```text
匯入欄位 ──按「套用匯入」──▶ 新回合厚度設定
                                  │
                                  └──之後修改只更新本回合分析

資料庫紀錄保存匯入當時的厚度，不由回合設定反向改寫
```

匯入表單在尚未套用時代表待處理資料；即時把它連動到目前回合會讓使用者在準備匯入時意外改變另一回合。匯入完成後若雙向同步，則會模糊「原始換算依據」與「目前分析參數」，也會破壞紀錄追溯性。因此只在明確按下「套用匯入」時帶入厚度。

## 3. 欄位與資料契約

| 欄位 | 語意 | 變更效果 |
|---|---|---|
| 匯入鋼板厚度 µm | 待套用匯入資料的換算基準，範圍 30–300 µm | 重新換算高度百分比資料；成功套用時保存到紀錄並帶入新回合 |
| 本回合鋼板厚度 µm | 目前選取回合的分析設定 | 重算該回合高度相關值與分析；不改寫資料庫量測紀錄 |

不新增欄位、端點或 migration。既有紀錄仍依其 `meta.stencil` 還原匯入值；重新套用記錄時需先確認厚度，明確套用後才建立或取代回合。

## 4. 行為驗收與相容性

| 使用情境／觸發 | 可觀察預期 | 錯誤／例外 | 應保留的既有行為 |
|---|---|---|---|
| 準備新匯入並輸入厚度 | 欄位標示為「匯入鋼板厚度」；選值不改變目前回合厚度 | 厚度非 30–300 µm 時阻止套用並提示修正 | 高度百分比按匯入時選定厚度換算 |
| 按「套用匯入」成功 | 新回合的厚度設定顯示匯入欄位的值 | 雲端保存失敗時不建立新回合 | 紀錄中繼資料保存匯入時厚度 |
| 修改本回合厚度 | 欄位標示為「本回合鋼板厚度」；目前回合重新計算 | 無效數值依既有欄位範圍驗證處理 | 原始雲端紀錄的匯入厚度不變 |
| 開啟既有量測紀錄重新匯入 | 匯入欄帶回紀錄厚度；確認並套用後才更新目前回合 | 紀錄沒有有效厚度且無可用預設時要求輸入 | 原始檔與既有紀錄保持不變 |

## 5. 安全、效能與發布

- 不改變登入、權限、API、D1／R2 寫入路徑或原始檔保留方式。
- 厚度重算沿用既有 `applyStencil`／匯入換算流程；沒有新增大資料計算。
- 發布方式沿用專案流程。本次 UI 文案修正需以建置產物驗證；未進行雲端發布或正式環境驗收。

## 6. 未決事項

本範圍沒有阻止實作的未決事項。若未來要讓使用者跨回合或跨裝置共用預設厚度，應另行定義設定擁有者、適用料號與覆寫規則。
