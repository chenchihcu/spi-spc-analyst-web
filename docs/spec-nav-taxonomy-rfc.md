## 1. Problem Statement & Goals

### 1.1 問題陳述

**FACT**

桌面主頁籤是 10 個同層按鈕，沒有分組標題：

`資料與規格` · `問題偵測` · `總覽` · `管制圖` · `製程能力` · `3D 錫膏模擬` · `深入分析` · `改善` · `AI 分析` · `分析報告`

使用者看到的其餘控制不是同一層選單：

| 畫面上的文字 | 實際控件 | 子項目 |
|---|---|---|
| 量測紀錄：未套用／已套用（受控）／舊資料・未受控 | `#stateSpi` 狀態膠囊，不可當選單按 | 無 |
| 座標檔：未套用／已套用（檢視，未受控）／已套用（身分相符） | `#statePlace` 狀態膠囊 | 無 |
| 記錄庫 ▾ | `#btnOpenRecModal` 開對話框 | 量測記錄、座標檔庫、規格與稽核 |
| 匯出 ▾ | `#btnOpenExportModal` 開對話框 | 見 §1.2 |
| 更多 ▾ | `#moreMenu`；窄螢幕改 `#moreSheet` | 桌面：雙欄、分享連結、我的分享、登出。手機另有整份頁籤分組 |
| 分析設定膠囊（預設文案含「範例資料」） | `#railChipSummary` 開 `#railSheet` | 試產回合、量測項目、元件群組、管制圖種類、子群組、焊墊、鋼板／規格 |
| 鋼板／規格 ✎ | `#railSpecBtn` 捷徑 | 進入資料與規格 → 設定的規格區 |

「範例」不是選單項。預設回合來源字串是 `範例資料`（`S.source`），出現在分析設定膠囊。範例載入鈕收在匯入、回合管理、AOI、DOE、GR&R 的「範例資料」摺疊裡。

**父層與子層現況**

| 父層 | 子層 | 子層裡的工作 |
|---|---|---|
| 資料與規格 | 匯入資料、設定、回合管理 | 設定內含介面主題、規格與鋼板、階梯鋼板、開孔、AI 金鑰／模型／配額 |
| 問題偵測 | 無子頁籤；頁內有嚴重度、面向、群組篩選 | `detectIssues()` 產出的面向含：子板位置、規格設定、單板異常、系統性能力、焊墊位置、趨勢漂移、重複犯焊墊、孤立極端焊墊、多變量離群、空間分布、刮刀方向、擦拭週期、對位、設計 DFM、量測、管制圖規則、形貌缺陷、停線時效、空間群聚 |
| 總覽 | 無 | 判定、KPI、優先問題、管制圖摘要、柏拉圖 |
| 管制圖 | 無頁內子頁籤；圖種在全站分析設定 | X̄-S、X̄-R、I-MR、P′、EWMA、CUSUM、Nelson |
| 製程能力 | 頁內分佈模型，不是子頁籤 | Cpk／Ppk、群組表、直方圖、機率圖、盒鬚圖 |
| 3D 錫膏模擬 | 頁內工具列 | 板號、外觀、著色、剖面、本板不良 |
| 深入分析 | 交叉驗證、進階分析、統計資料 | 交叉驗證：失效模式、交叉矩陣、高度×面積、位置熱圖、群組比較、X̄ 與 P′ 越界重疊。進階分析：面積比×轉移效率、Hotelling T²、焊墊 Cpk 排行、相關矩陣、對位、刮刀前後、擦拭週期、形貌指標、停線與鋼板壽命、LISA、關係圖。統計資料：異常點清單、板號×群組矩陣、雙邊 PPM／DPMO |
| 改善 | 試產比較、DFM 建議、實驗驗證 | 比較兩回合；DFM 開孔與印刷機閉環；AOI／X-ray、DOE、GR&R |
| AI 分析 | 無 | 主按鈕文字是「產生分析報告」 |
| 分析報告 | 無 | 章節、PDF、列印、Email |

手機「更多」用了另一套分組，和桌面父層不一致：

- 看證據：3D、交叉驗證、進階分析、統計資料
- 改善與驗證：試產比較、DFM、實驗驗證、AI 分析、分析報告
- 資料與設定：記錄庫、匯出中心、資料與規格
- 操作與帳號：主題、雙欄、分享、登出

底部四鍵是問題、總覽、管制圖、能力。管制圖與製程能力因此不在「看證據」裡。

**INFERENCE**

14 頁收成 10 頁時，父層沿用了「深入分析」「改善」這兩個剩餘名稱。子頁仍在，但父層不再描述子頁的工作。使用者會把 Hotelling T²、焊墊 Cpk、試產比較、GR&R、AI 金鑰找去錯誤的父層。

### 1.2 已確認的類別錯誤

下列「錯」指：**父層名稱承諾的工作，和子項實際工作不同**。計算、門檻與資料欄位都沒有錯。

| ID | 現在的位置 | 實際工作 | 判定 |
|---|---|---|---|
| C1 | 深入分析 → 交叉驗證 | 核對問題偵測是否互相支持 | 錯。這是問題查證，不是進階演算法 |
| C2 | 深入分析 → Hotelling T² | 多變量管制圖 | 錯。應與管制圖同層 |
| C3 | 深入分析 → 焊墊 Cpk 排行 | 製程能力排序 | 錯。應與製程能力同層 |
| C4 | 深入分析 → 雙邊 PPM／DPMO | 規格分側的能力指標 | 錯。應與製程能力同層 |
| C5 | 深入分析 → 3D 微觀形貌特徵 | 形貌統計指標 | 名稱撞車。不是 3D 錫膏模擬 |
| C6 | 改善 → 試產比較 | 兩回合對照 | 錯。比較不是改善動作 |
| C7 | 改善 → 實驗驗證（AOI／X-ray、DOE、GR&R） | 下游關聯、實驗、量測系統 | 錯。驗證不是改善建議 |
| C8 | 資料與規格 → 設定 → 介面 | 主題、雙欄狀態 | 錯。介面偏好不是資料或規格 |
| C9 | 資料與規格 → 設定 → AI 金鑰 | 服務商、模型、配額 | 錯。服務設定不是量測資料或錫膏規格 |
| C10 | AI 分析的「產生分析報告」 | 產生診斷敘述 | 用詞撞車。分析報告頁是 SPC 報告預覽與 PDF |
| C11 | 手機「改善與驗證」含 AI 分析、分析報告 | 診斷與交付 | 錯。這兩項不是改善，也不是實驗驗證 |
| C12 | 手機「看證據」不含管制圖、製程能力 | 證據只列出 3D 與深入分析子頁 | 標籤過寬。底部列才是主要證據頁 |
| C13 | 匯出「製程改善與工程分析」 | 問題清單、管制異常、各板統計、不良明細、補償參數、回合比較 | 混裝。清單是偵測資料，補償與比較才是改善產出 |
| C14 | 匯出「鋼板設計與 Layout」含 3D 快照 | PNG 是模擬畫面 | 錯。快照不是鋼板設計檔 |

**不是類別錯誤（維持）**

- 問題偵測排在總覽之前，且為預設頁。這是進入順序，不是放錯桶。
- 量測紀錄、座標檔是狀態，不是選單。記錄庫才是載入入口。
- 記錄庫的「規格與稽核」是持久紀錄，和量測、座標同屬資料庫，可留在記錄庫。
- 鋼板／規格 ✎ 是規格捷徑，指向正確。
- 改善 → DFM 建議與印刷機閉環，工作就是改善，留在改善。
- 分析報告與匯出中心都提供 PDF。頁面負責預覽與章節，匯出負責打包。兩處並存，不合併成一個父層。
- 管制圖種類放在全站分析設定，是範圍洩漏（見 C15），不是把管制圖頁放錯。

| ID | 現況 | 判定 |
|---|---|---|
| C15 | 管制圖種類（X̄-S 等）與試產回合、量測項目並列在全站分析設定 | 輕度錯位。圖種只服務管制圖；回合／量測／群組才是跨頁範圍。`RAIL_NOTE` 已在多頁聲明分析設定不適用，但圖種控制仍畫在同一張設定表 |

### 1.3 目標

| 目標 | 可驗收指標 |
|---|---|
| 父層名稱描述子項工作 | 交叉驗證不再掛在「深入」；試產比較不再掛在「改善」；GR&R／DOE／AOI 不再掛在「改善」 |
| 同一統計概念只掛一個分析父層 | T² 只在管制圖；Cpk 排行與分側 PPM 只在製程能力 |
| 「3D」只指錫膏模擬 | 形貌卡標題改為形貌指標，不帶「3D」 |
| 資料與規格只放資料與規格 | 介面偏好與 AI 金鑰離開該父層的設定區 |
| AI 與 SPC 報告用詞分開 | AI 主按鈕不再寫「產生分析報告」 |
| 手機分組與桌面父層使用同一套工作名稱 | 「更多」不再把 AI、報告放進改善與驗證；「看證據」改成不包含底部四鍵的名稱 |
| 匯出分組按產出物，不按聽眾職稱 | 3D 快照離開鋼板設計；問題／管制清單離開「製程改善」 |
| 主頁籤維持可橫向掃描 | 頂層分析頁仍為 10 個，不恢復 14 個並列頁籤 |

### 1.4 非目標

- 不改 `analyze()`、`detectIssues()`、管制界限、Cpk、Hotelling、LISA、DFM 公式與文案事實。
- 不新增頁面功能，不刪除現有圖、表、匯出格式。
- 不把 10 個主頁籤拆回 14 個頂層頁籤，也不在桌面頁籤列加回已刪除的分組文字標籤。
- 不改 hash 相容策略以外的路由契約；舊 hash 如何落地在實作階段沿用 `parseTabTarget()`，本文件只定目標父層。
- 不改 D1、R2、Worker API、登入或 `RecDB.create`。
- 不在本步驟改 `spi-spc.html`、測試或規則檔。
- 不把「範例資料」做成選單分類。
- 不把記錄庫、匯出的 ▾ 字形當成分類問題；是否改成不帶 ▾ 的按鈕，留到實作視覺稿。

## 2. System Architecture

### 2.1 工作角色

選單只允許五種角色。一個子頁只能有一個角色。

| 角色 | 使用者要完成的事 | 允許的父層 |
|---|---|---|
| 準備 | 把量測、座標、規格、回合放進這次分析 | 資料與規格、記錄庫 |
| 判定 | 這批過不過、問題在哪、證據是否一致 | 總覽、問題偵測 |
| 證據 | 用管制、能力、板面或製程跡象看同一批資料 | 管制圖、製程能力、3D 錫膏模擬、製程跡象 |
| 行動 | 改設計、改印刷，或拿另一回合對照、拿下游資料驗證 | 比較、改善、驗證 |
| 交付與偏好 | 交出報告或診斷，或改自己的介面與服務 | 分析報告、AI 診斷、更多 |

### 2.2 目標資訊架構

頂層仍是 10 個頁籤。變的是父層名稱、子頁歸屬，以及四個區塊的搬移。

```text
頂欄（準備與交付入口，不是分析頁）
├─ 量測紀錄狀態、座標檔狀態
├─ 記錄庫
│   ├─ 量測記錄
│   ├─ 座標檔庫
│   └─ 規格與稽核
├─ 匯出（見 §3.2）
└─ 更多
    ├─ 介面（主題、雙欄）          ← 自資料與規格搬入
    ├─ AI 服務（金鑰、模型、配額）  ← 自資料與規格搬入
    ├─ 分享連結、我的分享、登出

分析設定（跨頁範圍）
├─ 試產回合、量測項目、元件群組、焊墊
└─ 鋼板／規格捷徑
    管制圖種類改掛在管制圖頁內（C15）

主頁籤
1. 資料與規格
   ├─ 匯入資料
   ├─ 規格（原設定中的規格、鋼板、階梯、開孔）
   └─ 回合管理
2. 總覽
3. 問題偵測
   ├─ 問題清單（現況主體）
   └─ 交叉驗證          ← 自深入分析搬入（C1）
4. 管制圖
   ├─ 單變量（現有圖種與 Nelson）
   └─ 多變量            ← Hotelling T²（C2）
5. 製程能力
   ├─ 能力指標（現況）
   ├─ 焊墊排行          ← Cpk 排行（C3）
   └─ 分側 PPM          ← 雙邊 PPM／DPMO（C4）
6. 3D 錫膏模擬         （維持視覺重建；不接收形貌指標）
7. 製程跡象            ← 原「深入分析」更名，子頁只留一個
   └─ 面積比×轉移效率、相關矩陣、關係圖、對位、刮刀、擦拭、
      形貌指標、停線與鋼板壽命、LISA、異常點清單、板號×群組矩陣
8. 比較與行動          ← 原「改善」更名
   ├─ 回合比較          （C6：比較不再叫改善）
   ├─ 設計改善          （DFM、閉環；維持）
   └─ 實驗驗證          （C7：AOI／X-ray、DOE、GR&R）
9. AI 診斷             ← 原「AI 分析」更名（C10）
10. 分析報告
```

製程跡象裡的卡片不再分成「進階分析／統計資料」兩個子頁。搬走 T²、Cpk、PPM、交叉驗證之後，剩下的都是同一批製程跡象與明細，一個子頁就夠。若實作時單頁過長，只允許依卡片分組收合，不再發明第三個分析父層。

手機「更多」與桌面使用同一組工作名稱：

```text
其餘分析
├─ 3D 錫膏模擬
├─ 製程跡象
└─ 比較與行動
    ├─ 回合比較
    ├─ 設計改善
    └─ 實驗驗證
診斷與交付
├─ AI 診斷
└─ 分析報告
資料
├─ 記錄庫
├─ 匯出
└─ 資料與規格
操作與帳號
├─ 介面
├─ AI 服務
├─ 雙欄、分享、登出
```

底部四鍵維持問題、總覽、管制圖、能力，不重複放進「其餘分析」。

### 2.3 問題面向與頁面的對應

`detectIssues()` 的面向決定證據該出現在哪一頁。實作搬移時依這張表，不依卡片現在的 DOM 位置。

| 問題面向 | 目標頁 |
|---|---|
| 管制圖規則、趨勢漂移、多變量離群 | 管制圖（多變量離群的圖是 T²） |
| 系統性能力、焊墊位置 | 製程能力 |
| 刮刀方向、擦拭週期、對位、空間分布、空間群聚、形貌缺陷、停線時效、量測（體積與高度×面積不一致） | 製程跡象 |
| 設計 DFM | 比較與行動 → 設計改善 |
| 子板位置、單板異常、重複犯焊墊、孤立極端焊墊、規格設定 | 問題偵測；交叉驗證負責面向之間的對照 |

問題卡上的「前往」連結改指向目標頁。連結目標變了，卡片判定文字不變。

### 2.4 元件職責

| 元件 | 職責 |
|---|---|
| `.tabs` | 10 個頂層頁。`data-tab` 可保留 `deep`、`improve`、`ai`，可見名稱改為製程跡象、比較與行動、AI 診斷 |
| `#p-issues` | 新增子頁籤：問題清單、交叉驗證。交叉驗證 DOM 自 `#p-deep [data-subview=cross]` 移入 |
| `#p-control` | 新增子頁籤：單變量、多變量。T² 卡自進階分析移入 |
| `#p-capability` | 接收焊墊 Cpk 排行與分側 PPM 卡 |
| `#p-deep` | 可見名稱改製程跡象；移除 cross／adv／stats 三子頁，改為單一內容區 |
| `#p-improve` | 可見名稱改比較與行動；子頁改名回合比較、設計改善、實驗驗證。DOM 鍵 `compare`／`dfm`／`lab` 可保留 |
| `#p-ai` | 主按鈕改「產生診斷」 |
| `#p-data` | 子頁改為匯入資料、規格、回合管理。介面區與 `#aiSettingsCard` 移到更多所開的設定層 |
| `#railSheet` | 移除 `#selChart`、X̄-R 的 n 與劃分方式。這些欄位改放管制圖 → 單變量 |
| `#moreSheet` | 分組標題改為 §2.2 的四段 |
| `#exportCenterModal` | 分組改為 §3.2，匯出 `data-type` 不變 |

### 2.5 關鍵序列

1. 使用者在問題清單點「多變量離群」的證據連結 → 開啟管制圖 → 多變量，範圍仍是目前回合。
2. 使用者在問題清單點「設計 DFM」→ 開啟比較與行動 → 設計改善。
3. 使用者要改主題或 AI 金鑰 → 更多 → 介面或 AI 服務。資料與規格不再出現這兩區。
4. AI 診斷頁的「前往 AI 服務」開更多的 AI 服務區，不再呼叫 `setSub("settings")` 進資料頁。
5. 鋼板／規格 ✎ 仍開資料與規格 → 規格。

分享頁、郵件頁維持無頁籤的暫態面板，不納入這 10 類。

## 3. Data Model & Interfaces

### 3.1 沒有新的資料實體

分類校正不新增資料表、欄位或 API。既有回合、規格版本、問題卡 `cat`、匯出 `data-type` 都保留。

頁面狀態只加三個既有欄位的允許值，不改統計物件：

| 狀態欄位 | 現況 | 目標 |
|---|---|---|
| `S.tab` | `data issues overview control capability sim3d deep improve ai report` 及暫態 `mail share shares` | 鍵值不變。`deep` 的可見名改製程跡象，`improve` 改比較與行動，`ai` 改 AI 診斷 |
| `S.deepSub` | `cross \| adv \| stats` | 實作完成後不再切換子頁。舊值 `cross` 改開問題偵測的交叉驗證；`adv` 與 `stats` 開製程跡象 |
| `S.improveSub` | `compare \| dfm \| lab` | 鍵值保留。可見名改為回合比較、設計改善、實驗驗證 |
| `S.sub` | `import \| settings \| runs` | 目標為 `import \| spec \| runs`。舊 `settings` 若帶規格錨點則開規格，若帶 AI 錨點則開更多的 AI 服務 |
| `S.chart` | 圖種 | 仍是管制圖單變量的圖種，只是控制項離開 `#railSheet` |

### 3.2 匯出分組契約

`data-type` 與檔案格式不變。只改所屬群組標題。

| 目標群組 | `data-type` |
|---|---|
| 報告 | `rep-pdf`、`rep-pdf-lite`、`rep-md` |
| 診斷 | `ai-md` |
| 問題與管制清單 | `iss-xlsx`、`iss-csv`、`stats-csv`、`board-csv`、`def-csv` |
| 比較與改善 | `cmp-md`、`correction-json`、`dfm-csv`、`dfm-md` |
| 板面快照 | `snap-3d` |

「管理與決策層」「製程改善與工程分析」「鋼板設計與 Layout」三個標題刪除。一鍵打包的內容集合不變，只是不再用職稱當分類名。

### 3.3 對外介面

無新端點、無 webhook、無第三方契約變更。AI 請求路徑、匿名化與配額維持現況；只有進入金鑰設定的導覽目標改變。

### 3.4 路由字串

實作時要接受的深連結（可見行為）：

| 輸入 | 落地 |
|---|---|
| `#deep`、`#deep/adv`、`#deep/stats` | 製程跡象 |
| `#deep/cross` | 問題偵測 → 交叉驗證 |
| `#improve`、`#improve/compare` | 比較與行動 → 回合比較 |
| `#improve/dfm` | 比較與行動 → 設計改善 |
| `#improve/lab` | 比較與行動 → 實驗驗證 |
| `#ai` | AI 診斷 |
| 資料子頁 `settings`＋規格錨點 | 資料與規格 → 規格 |
| 資料子頁 `ai-cfg` 或設定頁 AI 錨點 | 更多 → AI 服務 |

舊的頂層 hash（`#cross`、`#adv`、`#stats`、`#compare`、`#dfm`、`#lab`）維持現行程式已規定的無效 hash 行為，不在本 RFC 重新啟用。

## 4. Security, Performance & Rollout

### 4.1 威脅模型

- 搬移不改變誰能讀量測、誰能寫規格、誰能呼叫 AI。AI 金鑰仍只在設定區顯示，不進分析頁正文。
- 問題卡連結只在既有頁面內切換，不把板號或焊墊放進新的外部 URL。
- 匯出分組只影響對話框標題，不改變檔案內容，也不新增下載類型。

### 4.2 效能與版面

- 頂層仍是 10 頁，避免頁籤列回到 14 頁的橫向溢出。
- 製程跡象合併成一頁後，卡片數量約為現在「進階分析＋統計資料」減去 T²、Cpk 排行。須沿用既有卡片間距，不可再包一層 `.card`。
- 管制圖、製程能力、問題偵測各增加一條子頁籤。子頁籤沿用 `.panel-subnav`，觸控高度維持 ≥ 44px。
- 圖表仍遵守先顯示面板再繪製。被隱藏的子頁不在 `offsetParent === null` 時畫 Chart.js。

### 4.3 推出與退回

沒有功能旗標。分類一次隨一個版本推出。

退回條件：問題卡的證據連結打開空白頁、或舊的 `#deep/cross` 與 `#improve/dfm` 無法落到 §3.4 的頁面。退回方式是還原頁籤名稱與 DOM 父層，不回寫資料庫。

### 4.4 實作前仍須核准的取捨

本 RFC 已選定「維持 10 個頂層頁、更名並搬四類區塊」。若核准範圍要改成下面任一項，先改本文件再實作：

1. 製程跡象仍拆成兩個子頁（跡象／明細），而不是合成一頁。
2. 介面與 AI 服務留在資料與規格，只用標題分成三區（與 `spec-settings-hub-rfc.md` 的設定 Hub 一致，本 RFC 的 C8、C9 不實作）。
3. 管制圖種類留在全站分析設定（C15 不實作）。

未核准前不修改介面。
